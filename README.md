# Сервис заявок на обслуживание оборудования

**Стек:** Python 3.11+, FastAPI, SQLite, Jinja2, Uvicorn. Обычные HTML-формы, собственный CSS,
без сборки фронтенда. SQLite входит в Python. Отдельный сервер базы данных не нужен.
Для занятия рекомендуем Python 3.13; локальные проверки исходной версии выполнены на Python 3.13.

## Быстрый запуск

Откройте терминал **в папке проекта**, где находится этот README.
Интернет нужен для первоначальной установки зависимостей.

### macOS / Linux

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m app --demo
```

### Windows (PowerShell)

```powershell
py -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe -m app --demo
```

Если `py` отсутствует, попробуйте `python`. Активация виртуального окружения не требуется:
команды явно вызывают Python из `.venv`.

Откройте **http://127.0.0.1:8000**. Остановка сервера — `Ctrl+C`.

`--demo` добавляет пять примеров только в пустую базу. Повторный запуск не дублирует примеры
и не меняет ваши заявки. Для запуска с пустым журналом при первом старте уберите `--demo`.
Обычный последующий запуск: `.venv/bin/python -m app`.
Если порт занят: `.venv/bin/python -m app --port 8001`.

На Windows в остальных командах заменяйте `.venv/bin/python` на `.venv\Scripts\python.exe`.
На некоторых дистрибутивах Linux компонент `venv` устанавливается отдельно средствами системы.

## Что уже работает

- Список заявок: сначала высокий приоритет, внутри — от новых к старым, и сводка по статусам.
- Создание заявки: оборудование, описание проблемы и приоритет.
- Карточка заявки с номером, датой создания и приоритетом.
- Статусы «Новая», «В работе», «Закрыта». Разрешён любой переход, в том числе возврат в работу.
- Приоритеты «Низкий», «Обычный», «Высокий». По умолчанию назначается «Обычный»;
  приоритет можно изменить в карточке.
- Понятные ошибки формы с сохранением введённого текста.
- JSON API и интерактивная документация на http://127.0.0.1:8000/docs.
- Сохранение данных после перезапуска приложения.

Название оборудования: от 1 до 120 символов. Описание: от 1 до 2000 символов.
Пробелы по краям удаляются, строка из пробелов не принимается. При создании всегда
назначается статус «Новая», а приоритет по умолчанию — «Обычный». Дата создания формируется
сервером и не меняется при смене статуса или приоритета.
Все даты хранятся и отображаются в UTC. Повторяющиеся заявки допускаются.

Поиск и фильтры оставлены для самостоятельных учебных доработок.

## Где данные

При запуске автоматически появляется `data/tickets.sqlite3` в папке проекта.
База и виртуальное окружение исключены из Git. Тесты работают с отдельными временными базами.

Для чистого старта остановите сервер и **переименуйте папку `data`**, например в `data-backup`.
Следующий запуск создаст новую базу. Для восстановления остановите сервер и верните прежнюю
папку на место, сохранив отдельно текущую. Не добавляйте резервные копии данных в коммиты.

## Проверки и разработка

Установите дополнительные инструменты (включают зависимости приложения):

```sh
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m pytest
.venv/bin/python -m ruff check .
.venv/bin/python -m ruff format --check .
```

Автотесты проверяют создание, смену статуса и приоритета через API и HTML, ошибки ввода,
сортировку по приоритету, обновление старой базы, сохранение после перезапуска,
демонстрационные данные, экранирование HTML и запрет изменений с другого сайта.
Предупреждения библиотек считаются ошибками. Версии зависимостей зафиксированы.
В GitHub Actions настроены такие же проверки на Python 3.11 и 3.13.

Запуск с автоматической перезагрузкой после изменения Python-файлов:

```sh
.venv/bin/python -m uvicorn app.main:create_app --factory --reload
```

Этот режим не добавляет примеры, но использует уже созданную базу. Изменения HTML/CSS
достаточно просматривать после обновления страницы. Для отладки в IDE выберите Python из `.venv`,
запуск модуля `app` и рабочую папку проекта; поставьте точку останова в обработчике создания заявки.

## Ручная проверка перед pull request

1. Запустите приложение и откройте журнал.
2. Создайте заявку с названием прибора, многострочным описанием и приоритетом «Высокий».
3. Убедитесь, что открылась карточка и заявка появилась в журнале.
4. Переведите её в работу, затем закройте и верните в работу. Измените приоритет на «Низкий».
5. Перезапустите приложение: заявка, последний статус и приоритет должны сохраниться.
6. Попробуйте отправить название из одних пробелов: приложение должно объяснить ошибку.
7. Откройте `/tickets/999999`: должна появиться страница «Заявка не найдена».

Браузер сам блокирует отправку пустых обязательных полей. Сервер дополнительно проверяет
ввод; автоматические тесты отправляют в том числе запросы в обход браузерной проверки.

## Структура

```text
app/
  __main__.py       Запуск сервера: python -m app
  main.py           Сборка приложения, запуск хранилища, обработка ошибок
  models.py         Модели, статусы и общие правила ввода
  repository.py     SQLite и демонстрационные данные
  api.py            JSON API
  web.py            Страницы и обработка форм
  templates/       HTML-шаблоны
  static/          Стили
tests/             Автоматические проверки
docs/TEACHER.md     Заметки преподавателю
.github/           Проверки pull request и шаблон описания
```

Синхронные обработчики работают с SQLite в потоке, не блокируя цикл обработки асинхронных
запросов. Каждая операция открывает и закрывает своё соединение; изменения выполняются
в транзакциях. Приложение создаётся функцией `create_app`: тест может передать путь
к отдельной базе без изменения глобальных настроек. Импорт кода сам по себе не создаёт файлов.

## API

| Метод | Адрес | Действие |
|---|---|---|
| GET | `/api/tickets` | Список заявок |
| POST | `/api/tickets` | Создать заявку, ответ 201 |
| GET | `/api/tickets/{id}` | Получить заявку |
| PATCH | `/api/tickets/{id}/status` | Изменить статус |
| PATCH | `/api/tickets/{id}/priority` | Изменить приоритет |

Создание:

```json
{"equipment": "Осциллограф · Э-204", "description": "Нет сигнала на втором канале.", "priority": "high"}
```

Поле `priority` необязательно. Изменение статуса:

```json
{"status": "in_progress"}
```

Изменение приоритета:

```json
{"priority": "low"}
```

Значения статуса: `new`, `in_progress`, `closed`. Значения приоритета: `low`, `normal`, `high`.
Ошибки данных — 422, отсутствующая заявка — 404.
Поля, которых нет в модели запроса, отклоняются. HTML-формы после успешной отправки
возвращают перенаправление 303: обновление страницы не повторяет отправку.

## Границы учебной версии

Приложение запускается на `127.0.0.1` для локальной работы одного студента.
Авторизации, разделения пользователей, пагинации и развёртывания в интернете здесь нет.
Для публичного сервиса потребуется отдельная доработка. Начальная схема создаётся автоматически;
системы миграций пока нет. При изменении схемы нужно обеспечить обновление существующей базы,
а не только поменять `CREATE TABLE`. Колонка приоритета добавляется в уже существующую базу
автоматически, старые заявки получают приоритет «Обычный».

Интерфейс работает без внешних шрифтов, CDN и JavaScript. Страница `/docs` использует
внешние ресурсы Swagger UI; для неё нужен интернет. Основной интерфейс и API после установки
зависимостей работают локально без сети.
